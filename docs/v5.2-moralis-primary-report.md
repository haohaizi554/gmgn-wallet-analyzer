## Root Cause

此前真实运行出现：

```text
Moralis ConnectionResetError(10054)
→ GMGN wallet_activity=[]
→ SUCCESS tokens=0
```

原因不是“钱包真的没有交易”，而是三条实现错误叠在一起：

1. `WalletAnalysisService.analyze()` 先同步打 GMGN stats/profits，再采历史。所以日志永远是 GMGN 先于 Moralis。
2. `HttpProviderMixin` 对 10054 只请求一次。Moralis 失败后 `collect_wallet_swaps` 返回空 `WalletSwapIndex`。RPC fallback 被包在 `if helius.enabled` 里，没有 Helius Key 时根本不会走链上兜底。
3. 服务层把空索引当成“需要 GMGN activity”。GMGN 空页没有 coverage。`analyze()` 只要没抛异常就 `SUCCESS`。

空 `[]` 与“请求失败所以什么都没拿到”无法区分，于是生成一份看起来成功、实际可能全错的 Excel。

完整调用链见 `docs/v5.2-root-cause-audit.md`。

## Provider Routing

正式默认：

```text
Moralis          主索引（有 Key 且 ENABLE_MORALIS=true）
    ↓ 网络失败 / 401 / circuit open
Solana RPC       硬兜底（钱包级 signatures + 有限 getTransaction）
    ↓ 仍失败且 HELIUS_API_KEY 可用
Helius           可选增强（先 capability probe；PLAN_UNAVAILABLE 立即 skip）
    ↓
Unknown Empty    PARTIAL / FAILED
                 默认不再走 GMGN history
```

启动 Job 日志：

```text
history.primary=MORALIS
history.fallback=SOLANA_RPC
moralis.enabled=true|false
helius.optional=true
gmgn.deep_history=false
```

`ENABLE_GMGN_DEEP_HISTORY_FALLBACK` 默认 `false`。  
`ProviderPriorityRegistry.WALLET_SWAPS` 现为 `moralis → solana_rpc → helius → gmgn`，并且 `collect_wallet_swaps` 真正按这条链走，不再只是配置表。

## Retry

网络瞬时错误（`ConnectionResetError` / `ConnectionError` / timeout / 408 / 5xx）：

```text
attempt 1 → 0.5s + jitter
attempt 2 → 1.0s + jitter
attempt 3 → 2.0s + jitter
```

- 401：`AUTH_FAILED`，不网络重试（可轮换下一把 Moralis Key）。
- 403：`PLAN_UNAVAILABLE` 或 `PERMISSION_DENIED`，不网络重试。
- 429：尊重 `Retry-After`；过长则交给 limiter cooldown，禁止无限立即 retry。
- Moralis circuit：连续 3 次网络/5xx → `CIRCUIT_OPEN` 30 秒 → `HALF_OPEN` 单探针。其它 Provider 不受影响。

单元测试：第一次 10054、第二次 200 → 2 次请求、不 fallback。  
三次 10054 → `fallback=SOLANA_RPC`。

真实跑钱包时日志同样出现：

```text
moralis ... attempt=1 NETWORK_TRANSIENT_ERROR ConnectionError
retry=0.58s
```

随后 Key 返回 401，正确停止网络重试并 fallback RPC，而不是 GMGN。

## Empty Semantics

| 情况 | coverage | Job |
|------|----------|-----|
| Provider 成功 + 分页结束 + 0 笔 | `verified_empty=True` `complete=True` | **SUCCESS tokens=0** |
| Moralis 失败 + RPC 失败 + GMGN [] | `unknown_empty` | **FAILED**（有部分数据则为 PARTIAL） |
| Moralis 失败 + RPC 拿到交易 | `complete=True` `fallback_used=True` | SUCCESS / PARTIAL 按质量门 |

`DataQualityGate` 在导出前裁决。不再用“没抛异常 = SUCCESS”。

## Correctness Fixes

### SELL

删除 `if declared == "SWAP": return BUY`。方向只看 wallet-side delta：

- token > 0 且 quote < 0 → BUY
- token < 0 且 quote > 0 → SELL
- 否则 `unknown_swap` / transfer

回归：Token -10 / USDC +100 → SELL。

### Quote

不再把 SOL/WSOL/USDC/USDT `sum()` 后写成 `symbol=SOL`。选取绝对值最大的单条 quote leg，保留真实 mint/symbol。

USDC/USDT 成交直接 `cost_usd = quote_amount`（DERIVED）。  
SOL/WSOL 保留 `cost_sol`；没有历史 SOL/USD 时 `cost_usd=无法验证历史美元成本`。  
Moralis 自带 `usdAmount` / `usdPrice` / `totalValueUsd` 优先保留。

### Report Window / Lifetime First Buy

报告 7d/30d/90d 只决定本期 Token 集合与 report trades。  
First Buy 仍用生命周期最早 Buy。  
100 天前 Buy + 3 天前 Sell，7d 报告会出现该 Token，report trades 只有 Sell。

### Warm Cache

新增 `wallet_history_events`。增量：从 newest 拉到 known signature 停止，再 `new head + cached body` 去重合并。  
`wallet_history_state` 的 oldest 不会被本次 newest 覆盖。

### Multiple Token Account

`parse_verified_transaction` 对同一 mint、钱包名下全部 ATA 求和后再算 delta。5 + 3 → 8。

### GMGN / Helius

- GMGN stats/profits 与主历史并行，失败不阻断。
- GMGN `activity=[]` 不再等于 verified empty。
- 无 `HELIUS_API_KEY`：GUI 显示 `NOT CONFIGURED (Optional)`，不是红色 ERROR，任务可运行。

钱包：GUI 示例地址 `7EcDhSYGxXyscszYEp35KHN8vvw3svAuLKTzXwCFLtV`  
环境：`ENABLE_MORALIS=true`，2 把 Moralis Key，无 Helius Key，公共 Solana RPC。

|----|------|------|
| status | **FAILED** | **FAILED** |
| tokens | 0 | 0 |
| elapsed | 21.7s | 12.6s |

这不是回归到旧 bug。旧路径会在这里输出 **SUCCESS tokens=0**。现在明确 **FAILED + unknown_empty**。

失败原因（真实限制，不是路由错误）：

1. Moralis 先 10054（已重试），随后两把 Key 对 `/account/.../swaps` 返回 **401 AUTH_FAILED**。当前 Key 无法作为 Solana Gateway wallet swaps 主索引。
2. 公共 `api.mainnet-beta.solana.com` 在有限 `getTransaction` 后 **429**，RPC fallback 未能完成覆盖。
3. 无 Helius Key，optional enhance 不参与。

因此 **未能完成 20+ Token 的完整真实抽样**。质量门拒绝了假成功。

## Known Limitations

1. **当前本地 Moralis Key 对 Solana wallet swaps 返回 401。** 在 Key 具备该产品权限之前，主索引无法在真实环境跑通。请在 Moralis 控制台确认 Solana Gateway / wallet swaps 已开通，并在设置页点“测试数据源”。
2. **公共 Solana RPC 会 429。** 硬兜底能工作，但不适合大钱包全量 `getTransaction`。建议换更高限额 RPC URL（`SOLANA_RPC_URL`），或在有套餐时启用 Helius 作为 optional enhance。
3. RPC fallback 仍是钱包级索引 + 有限深挖（签名上限 / 校验笔数上限），不是每个 Token 的完整链上史。这是有意避免“265 Token × 全历史”的暴力扫描。
4. 没有历史 SOL/USD 曲线源时，SOL 成交可以保留真实 `cost_sol`，美元成本仍可能是“无法验证历史美元成本”。不会用当前价冒充成交价。
5. 示例钱包未能完成 5 Token / 15 Token 人工抽检，因为核心历史源在本次真实环境都不可用。抽检应在 Moralis 401 解除或 RPC 不再 429 之后重做。
6. `.env` 已在 `.gitignore`；正式包不得包含 Key。`.env.example` 只有空占位。

## 结论

V5.2 已把主链、兜底链、辅助链分开，并且堵住了最危险的假成功。  
在 **Moralis wallet swaps 可用 + RPC 不 429** 的组合下，核心分析可以不依赖 GMGN 和 Helius。  
当前这台机器上的 Moralis Key 尚未通过 wallet swaps 鉴权，所以真实 20+ Token 抽样被质量门拒绝——这正是这次要修的行为。
